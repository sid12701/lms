Authentication and Error Envelope

Use POST /api/v1/auth/login for human users and POST /api/v1/auth/token for LSP API clients. Protected APIs require Authorization: Bearer <accessToken>. Mutating idempotent LSP APIs use Idempotency-Key as a UUID v4 value.

Refresh token is held in the server-issued refresh cookie. CORS exposes X-Correlation-Id, pagination headers, and content disposition.

Loan Approval Rules

Auto-approval fires only when all intake-required documents have just become complete and the application is in INITIALIZED or AWAITING_APPROVAL. If every rule passes, the system moves INITIALIZED -> AWAITING_APPROVAL -> APPROVED_PENDING_DISBURSAL, creates the loan account, and generates the repayment schedule. If rules fail while already awaiting approval, it moves to REJECTED with rejection_reason_json.failedRules.

Rule codeRequirement
PRODUCT_INACTIVESelected loan product must exist and be ACTIVE.
LSP_INACTIVEAuthenticated/requested LSP must be ACTIVE.
LSP_PRODUCT_MAPPING_INACTIVEThe product must be mapped to the LSP and the mapping must be enabled.
LOAN_AMOUNT_OUT_OF_RANGERequested amount must be within product minPrincipal and maxPrincipal.
LOAN_TENURE_OUT_OF_RANGERequested tenure must be within product minTenureMonths and maxTenureMonths.
BORROWER_REQUIRED_FIELDS_MISSINGBorrower must have name, PAN, mobile, Aadhaar, address, city, state, zip, income, reference name, and reference number.
REQUIRED_DOCUMENTS_NOT_UPLOADEDAll intake-required checklist documents must be complete.
BORROWER_HAS_OPEN_LOANBorrower cannot already have another open loan across LSPs.

Required documents

PAN_CARD, AADHAAR_FILE, ADDRESS_PROOF, INCOME_PROOF, BANK_STATEMENT, SELFIE_PHOTOGRAPH, KFS, LOAN_AGREEMENT

Upload constraints: PDF/JPEG/PNG globally, 10 MiB max; PAN and Aadhaar are PDF/JPEG only and 5 MiB max; loan agreement is PDF only. File name cannot be blank or contain .., and file bytes must match declared MIME type.
